title 01 - Platform Core & Services simplified diagram for other subteams

interface ClientUI <<interface>> {
  + clientUI team
  + all user interaction occurs here
  + send (request)
  + receive (update)
}

interface clientGame <<interface>> {
  + rules and validation
  + client instance of the validation logic
  + validate(move) : Bool
}


class ClientCore <<service>> {
  + handle local requests from user
  + communicate to and from server for remote requests
  + store local information for the UI
  + check moves are valid before sending to the server
  + send(message) : String
  + receive(String) : message
  + check(move) : validate(move) with clientGame
  
  
}
note left of ClientCore
The exact distribution of functions between the main program
and the listener thread will be determined when coding starts,
this distribution is not final.
end note

class ServerCore <<service>> {
  + Main functional component of the Platform Core
  + All communication between services is handled here
  + direct events between services
  + send and receive user communications
  + reply to User requests
  + send(ID, message) : String
  + receive(ID, String) : ID, message
}

class NETWORK <<stub>> {
  + Messages are sent and received over the network by TCP.
  + For communicating between threads and different programs
  + on the same computer using actual networking is the best
  + solution.
}

note left of NETWORK
dotted lines from Chat, GameLobby and Game
represent events sent via ServerCore to the user,
separated out for clarity.
end note


class Chat <<service>> {
  + send chat messsages to all users on it's list
  + List<int> users  : user ID's 
  + List<int> user IP addresses
  + receiveContent(content) : sendMessage(content,users)
  + sendMessage(content,users) : send the chat message \n to everyone on the list
}

class Database <<stub>> {
  + returns login Boolean
  + scoreboard updating 
  + storeData(): void
  + retrieveData(): void
}

class GameLobby <<service>> {
  + Separate chat and UI style to the main lobby
  + display game info
  + receiveContent(content) : void
  + requestJoin() : join matchmaking
}

class matchmaking <<service>> {
  + put user in the queue
  + when a match is found, route the join query via gamelobby
  + then if they accept create a new Game instance
  + and move both players over
}

class Game <<service>> {
  + send and recieve turn updates
  + check the validity of moves
  + send updated game state to both players
  + local chat instance
  + allow user to return to lobby or quit
}

interface GameEngine <<interface>> {
  + Rules and Validation
  + validateMove(move) : Boolean
  + updateGame(move) : new game state, next turn value
}

NETWORK ..> ServerCore
ServerCore ..> NETWORK

GameLobby --> Chat

GameLobby ..> NETWORK

matchmaking --> Game

GameEngine --> Game
