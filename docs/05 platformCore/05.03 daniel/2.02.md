# Data Model & Persistence Layer – Architecture Documentation

## Overview

This document describes the data model and persistence layer of the Platform Core system. All core domain entities — `User`, `PlayerStats`, `GeneralStats`, and `GameHistory` — extend the base `Record` class, enabling them to be managed uniformly through the generic `Store<T>` persistence abstraction. Each entity type is written to its own dedicated stub file, with file paths defined centrally in the `Constants` class.

---

## Base Class

### (A) Record
The abstract base for all persistable domain objects. Every entity stored in the system inherits from `Record`, giving it a unique ID and a consistent interface for the `Store<T>` layer.

| Member | Visibility | Type | Description |
|---|---|---|---|
| `id` | private | int | Unique record identifier |
| `Record(int)` | public | void | Constructor |
| `getID()` | public | int | Returns the record's ID |
| `setID(int)` | public | void | Sets the record's ID |

**Subclasses:** `User`, `GeneralStats`, `GameHistory`, `PlayerStats` (via dependency chain)

## Persistence Infrastructure

### (C) Store\<T\>
The single, generic persistence abstraction used by all `Record` subtypes. Each entity type is given its own `Store` instance, pointing to its own stub file via the `filePath` field. This means `User`, `GeneralStats`, `GameHistory`, and `PlayerStats` each have an independent store with no cross-contamination of data.

| Member | Visibility | Type | Description |
|---|---|---|---|
| `records` | public | Map | In-memory map of stored records |
| `filePath` | public | String | Path to the backing stub file |
| `Store(String)` | public | void | Constructor — accepts file path from `Constants` |
| `find(Predicate)` | public | List | Query records by predicate |
| `create(T)` | public | void | Add a new record |
| `delete(T)` | public | void | Remove a record |
| `update(T)` | public | void | Update an existing record |
| `loadAll()` | public | Store\<record\> | Load all records from file into memory |
| `saveAll()` | public | void | Flush all in-memory records to file |

**Pattern:** Each entity's `Store` is instantiated with the relevant constant from `Constants`, e.g. `new Store<User>(Constants.USERFILEPATH)`.

### Persistence Stubs

| Stub | Backed By | Entity | Constant |
|---|---|---|---|
| `UserStub` | `Store<User>` | `User` | `Constants.USERFILEPATH` |
| `game History stub` | `Store<GameHistory>` | `GameHistory` | `Constants.GAMEFILEPATH` |
| `Player Stats stub` | `Store<PlayerStats>` | `PlayerStats` | `Constants.PARTICIPANTSFILEPATH` |

Stubs simulate a database layer for development and testing. In production these would be swapped for real database adapters without changing the `Store<T>` interface.

## Data Flow: Write & Read Lifecycle

### Writing a Record
1. A domain object (e.g. `PlayerStats`) is created or updated in memory.
2. The relevant `Store<T>` instance calls `create(T)` or `update(T)` to update the in-memory `records` map.
3. `saveAll()` is called, serialising the map and writing it to the stub file at the path defined by `Constants`.

### Reading a Record
1. `Store<T>.loadAll()` reads the stub file at `filePath` and deserialises it into the in-memory `records` map.
2. `find(Predicate)` queries the in-memory map and returns matching records.
3. The calling class (e.g. `PlayerStats`, `GameSessionManager`) receives the result and works with the hydrated domain objects.

## Dependency Summary

```
Record (base)
  ├── User          → Store<User>         → UserStub          (USERFILEPATH)
  ├── GeneralStats  → Store<GeneralStats> → (internal)
  ├── GameHistory   → Store<GameHistory>  → GameHistoryStub   (GAMEFILEPATH)
  └── PlayerStats   → Store<PlayerStats>  → PlayerStatsStub   (PARTICIPANTSFILEPATH)

PlayerStats  depends on  GeneralStats  (for rank computation)
PlayerStats  depends on  Store<T>      (for persistence)
User         depends on  Helper        (for password hashing)
Helper       depends on  Constants     (for HASHALGORITHM)
Store<T>     instantiated with         Constants.*FILEPATH
```
